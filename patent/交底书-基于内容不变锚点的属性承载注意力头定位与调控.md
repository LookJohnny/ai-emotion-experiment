## 一、技术领域

本发明涉及人工智能技术领域，具体涉及以下几个方面：

- 在基于 Transformer 的大语言模型中，定位承载文本属性（如情绪、语气、态度）的注意力头；
- 利用定位结果，对模型生成文本的属性进行调控；
- 利用定位结果，对模型内部的属性状态进行实时读出。

---

## 二、背景技术

### 2.1 背景

大语言模型生成的文本带有情绪、语气等属性。情感陪伴、客服、虚拟形象驱动、AI 安全监测等应用，需要知道这些属性在模型内部由哪些部件承载，以便：

1. 调控生成文本的属性，例如让回复更温和，或保持指定的情绪；
2. 在文字生成之前或生成过程中，读出模型内部的属性状态，用于驱动表情或提前预警。

### 2.2 现有技术及其缺点

**现有技术一：Inference-Time Intervention（ITI）**

来源：Li 等人，“Inference-Time Intervention: Eliciting Truthful Answers from a Language Model”，NeurIPS 2023，arXiv:2306.03341。

做法：

1. 对每个注意力头的输出训练线性探针；
2. 按探针准确度选出前 K 个头；
3. 推理时沿真/假两类均值差方向平移这些头的输出。

缺点：

1. 需要为每个头单独训练探针。
2. 探针读取的位置和属性本身的字面表达处于同一位置，所以准确度高的头，可能只是在“读字面”（比如直接看到“生气”这个词），并不一定把属性传递到后续文本。
3. 选头依据是可读性，而不是承载程度。

**现有技术二：情绪电路发现与控制**

来源：Wang 等人，“Do LLMs ‘Feel’? Emotion Circuits Discovery and Control”，arXiv:2510.11328，2025。

做法：

1. 构造事件语义决定情绪、参与者和情境固定的数据；
2. 在用户输入的最后一个 token 处读取残差流；
3. 逐个将注意力头置零（因果消融），测量其对情绪方向投影的影响，以此给头排序；
4. 在最后一个 token 位置注入情绪差向量。

缺点：

1. 需要逐头做干预实验，计算量随头数线性增长。
2. 读取位置是输入末尾，无法区分“编码情绪”和“把情绪传递到后续内容”的部件。
3. 干预只发生在特定位置。

**现有技术三：对比激活加法（CAA）、表征工程**

来源：如 Zou 等人 2023 年的 Representation Engineering。

做法：在残差流的整层上加入属性方向。

缺点：

1. 作用于整层，粒度粗。
2. 容易影响流畅度和事实性。
3. 不提供部件级的定位。

**现有技术四：基于激活修补（activation patching）的定位**

做法：对每个候选部件分别做“供体→受体”替换实验。

缺点：计算量大。在研发方的实验中，仅在 512 个头的层窗口内做单头修补，就耗时约 2682 秒（单张 RTX 5090 GPU），峰值显存约 10.4 GiB。

### 2.3 本发明要解决的技术问题

1. **如何以低计算成本、不训练逐头探针、不做逐头干预的方式，定位真正把文本属性传递到后续内容的注意力头**，并且避免把只读取字面属性词的头误判进来。
2. 如何利用定位结果，稳定、特异、不明显损害流畅度地调控生成属性。
3. 如何把上述定位方法迁移到新的模型上，而不必重复昂贵的因果搜索。

## 三、技术方案

### 3.1 核心构思

构造一组输入。每个输入由三段依次组成：

1. **属性承载段**：带有目标属性；
2. **共享前缀段**：可选；
3. **内容不变锚点段**：在同一内容组内逐 token 完全相同。

锚点段在同一内容组的不同属性变体之间逐字相同，其字面不携带属性信息。因此，在锚点位置读到的属性差异，**只能来自模型经注意力从前文搬运来的信息**。

在锚点位置收集每个注意力头的输出后，用一个**组内属性方差占比**统计量给头排序。这个统计量只需前向计算，不需要训练，也不需要干预；排名靠前的头即为属性承载头。

随后，可以在这些头上，于锚点位置以及之后每个生成步**持续**注入属性导向向量，以调控生成；也可以在这些头或其所在层上读出属性状态。

### 3.2 步骤一：构造锚点对照样本集

1. 选取 S 个内容组（场景）s = 1…S。每个内容组对应一段共享的事实或指令前缀 P_s，例如“请根据下面事实，以第一人称写一段简短回应……事实：……”。
2. 对每个内容组，构造 K 个属性变体 k = 1…K，其中包含一个参照属性（例如中性）。
   - 每个变体有一个属性承载段 L_{s,k}，例如“我挺开心的，以后买东西方便多了。”或“真让人火大……”。
   - 可选地，每个变体还可以有一个改写版本，例如不含情绪类别词的改写。
3. 为每个内容组构造一个锚点段 A_s，例如“便利店扩大一倍，门口长椅被撤掉。我的看法是：”。A_s 在该组所有 K 个变体中逐 token 相同。
4. 将输入拼接为 X_{s,k} = Template(P_s) ⊕ L_{s,k} ⊕ A_s。其中 Template 为模型的对话模板，例如把 P_s 放在用户回合，把 L_{s,k} ⊕ A_s 放在助手回合的开头。
5. **校验**：同组内 A_s 在分词后的 token 序列完全一致。若属性段末尾与锚点段开头发生分词合并，则调整锚点开头（例如加标点），或只取完全落在锚点区间内的 token。

### 3.3 步骤二：前向计算并收集锚点位置的头输出

1. 将每个 X_{s,k} 以教师强制方式送入目标模型，做一次前向计算，不需要生成。
2. 对每一层 l、每个注意力头 h，取该头在锚点段各 token 位置的输出，并在锚点 token 上取平均，得到向量 o_{s,k}^{l,h}（维度为 d_head）。
   - 实施例中，“头的输出”取该层注意力输出投影矩阵 W_O 的输入中属于头 h 的那一段。
   - 替代地，也可以取该头经 W_O 映射后对残差流的贡献 o·W_O^{(h)}。
3. 可选：同时收集各层残差流在锚点位置的平均向量，用于步骤四的层窗口选择。

### 3.4 步骤三：计算组内属性方差占比并排序

对每个 (l, h)，记 o_i 为第 i 个样本的向量，s(i) 为其内容组，k(i) 为其属性，计算：

- 总均值：ō = mean_i o_i
- 内容组均值：μ_s = mean_{i: s(i)=s} o_i
- 组内残差：r_i = o_i − μ_{s(i)}
- 属性均值（在组内残差上）：m_k = mean_{i: k(i)=k} r_i
- 总平方和：SS_tot = Σ_i ‖o_i − ō‖²
- 内容平方和：SS_scn = Σ_i ‖μ_{s(i)} − ō‖²
- 属性平方和：SS_attr = Σ_i ‖m_{k(i)}‖²

**承载分数 C(l,h) = SS_attr / (SS_tot − SS_scn)**，即在扣除内容差异之后，属性能解释的方差比例，取值 0–1。

按 C(l,h) 从高到低给全部注意力头排序，取前 N 个，或取 C 超过阈值的头，作为属性承载头集合 H*。

可选的第二指标：

- 以 o^{l,h} 为特征，按内容组分组做交叉验证，训练一个多分类线性分类器，得到属性可读性 AUROC。
- 与 C 加权组合，或作为并列排序依据。
- 实施例中，两种排序都能找回下文所述的因果承载头，其中 C 的效果更好。

### 3.5 步骤四（可选）：层窗口选择

1. 对每层残差流在锚点位置的平均向量，计算属性可读性，可以用上述 AUROC，也可以用 SS_attr / SS_tot。
2. 以可读性峰值所在层为中心，取一个层窗口，例如相对深度 0.3–0.7，或峰值层 ±4 层。
3. 可选：把 H* 限制在该窗口内。

实施例中，三种不同模型的峰值都位于相对深度 0.43–0.56，峰值之后可读性下降。

### 3.6 步骤五（应用一）：持续注入式属性调控

1. 对每个 h ∈ H*，计算导向向量：

   v_h = mean(o^{h} | 目标属性) − mean(o^{h} | 参照属性)

   取在锚点位置、对应样本集上的均值差。
2. 在生成时，对每个 h ∈ H*，在其输出上加 λ·v_h（加在 W_O 之前的头输出切片上）。注入位置包括：
   - 输入中锚点（或提示末尾）的位置；
   - **之后每一个新生成 token 的位置**，即持续注入。
3. λ 在验证集上选取，兼顾属性强度和流畅度。实施例中 λ = 2。
4. 可选：只在前 M 个生成 token 内注入，以降低对事实一致性的影响；也可以按生成进度逐步衰减 λ。

### 3.7 步骤六（应用二）：属性状态读出

在 H* 所在的层或层窗口上，训练或直接使用属性方向，读出模型在生成前或生成中的属性状态。读出结果可以用于：

- 驱动虚拟形象或机器人的表情；
- 安全监测预警；
- 调控的闭环反馈，例如读数超过阈值时减小 λ。

### 3.8 步骤七（应用三）：新模型上的快速定位

对一个新的目标模型，只需用同一锚点对照样本集重复步骤二到步骤四，即可得到该模型的属性承载头和层窗口，无需逐头修补或逐头消融。

## 四、有益效果（附实验数据）

实验模型和数据：

- **模型**：Qwen3-4B-Instruct-2507（36 层 × 32 头）、Qwen3-1.7B（28 层 × 16 头）、Llama-3.2-1B-Instruct（16 层 × 32 头）。
- **数据**：120 个中文场景 × 4 种情绪（喜悦、悲伤、愤怒、中性）× 2 种改写。
  - 探索集：80 个场景；
  - 留出集：40 个场景，话题与探索集不同。
- **流程**：分析方法与检验条件在查看留出集数据之前已书面固定并提交版本库（commit f32ddd3、d368ffa）。

### 4.1 无需干预即可找回因果承载头

在 Qwen3-4B 上，研发方此前用激活修补和持续导向（见 4.3）独立确定了 12 个情绪承载头。用本方法的承载分数 C 在留出集上给全部 1152 个头排序：

| 指标 | 结果 |
|---|---|
| 12 个因果头中落入前 10% 的个数 | **8 个** |
| 置换检验（从同一层窗口 L12–27 随机抽 12 个头，10000 次） | p < 0.0001 |
| 关键头 L14H25 的排名 | 第 2 |
| 探索集与留出集的头排名一致性（Spearman ρ） | 0.93，换话题后仍稳定 |

### 4.2 计算成本显著降低

| 方法 | 覆盖范围 | 硬件 | 耗时 |
|---|---|---|---|
| 现有方法（单头激活修补） | 512 个头的窗口 | RTX 5090 | 约 2682 秒 |
| 本方法 | 全部 1152 个头 | Apple M4 笔记本 | 前向特征提取约 282 秒（640 条样本）；承载分数为闭式计算，秒级完成 |

本方法每条样本只需一次前向计算，计算量与头数无关。逐头修补或消融的计算量则与头数成正比。

### 4.3 持续注入的调控效果

在 Qwen3-4B 的 12 个承载头上持续注入，λ = 2，在封存测试集上（40 个场景，360 条续写，由两路独立的大语言模型盲评打分，评分者间相关 0.84–0.97，尚未做人工校准）的结果：

| 对照 | 愤怒程度变化（满分 4） | 95% 置信区间 |
|---|---|---|
| 相对幅度匹配的随机方向 | **+1.19** | [0.96, 1.42] |
| 相对不干预 | +1.19 | [0.95, 1.43] |

其他结果：

- **特异性**：愤怒的上升大于喜悦（差 +1.38）、大于悲伤（差 +0.96），两个置信区间的下限均大于 0。
- **流畅度**：+0.06，置信区间 [−0.13, 0.28]，无明显损害。
- **对照：只在锚点位置做一次性干预**：在验证集上，只在锚点位置把这 12 个头的输出替换为愤怒供体样本的输出，生成后仅 +0.04，置信区间 [−0.07, 0.16]，几乎无效。这说明作用必须覆盖生成过程，“持续注入”是取得效果的关键特征。
- **局限**：事实一致性均值下降 6.2 个百分点（置信区间跨 0）。实施例中可以采用 3.6 第 4 项的限位或衰减方案缓解。

### 4.4 跨模型普适

在三个模型上，锚点位置的属性可读性都在相对深度 0.43–0.56 达到峰值，随后下降。这为步骤四的层窗口选择提供了跨模型依据，三个模型的留出集检验均通过。

### 4.5 定位结果反映的是“搬运”，而不是字面

在锚点位置，属性只解释约 3–5% 的方差（内容约占 90%），但仍能以 AUROC ≥ 0.99 读出。这说明：

- 按方差大小或激活强度挑选部件，主要会挑到承载内容的部件；
- 承载分数在扣除内容之后计算，所以能把真正的属性承载部件挑出来。

## 五、实施例

### 实施例一：Qwen3-4B-Instruct-2507，愤怒属性

1. **数据**：120 个场景，每个场景是一个“收获 + 失去所珍视之物 + 他人不当决定”的三要素混合事件。四种情绪的属性段由大语言模型起草，并经 8 轮独立大语言模型盲评筛选；尚未做人工审校。锚点为该场景事实摘要加“我的看法是：”。探索集与留出集按话题划分。
2. **特征**：bfloat16 精度，教师强制前向计算。用 forward_pre_hook 读取 o_proj 的输入并切分为 32 个头（每头 128 维），在锚点 token 上取平均。
3. **排序**：按 3.4 计算 C(l,h)。结果包括：
   - 前 10% 中包含 L14H25、L17H16、L17H19 等头；
   - L14H25 在描述性分析中，有 48% 的注意力从锚点指向属性段。
4. **调控**：在 12 个承载头上以 λ = 2 持续注入愤怒−中性导向向量，最大生成 64 个 token。效果见 4.3。

### 实施例二：Qwen3-1.7B 与 Llama-3.2-1B-Instruct

以相同样本集重复步骤二至四。可读性峰值分别位于第 15 层（相对深度 0.56）和第 7 层（相对深度 0.47）。每个模型在 Apple M4 上的特征提取时间约为 1 至 2 分钟。

### 实施例三（可选扩展）：其他属性

把“情绪”替换为其他可在属性段中表达、且需要传递到后续内容的属性，同样适用：

- 语气：正式 / 随意；
- 礼貌程度；
- 态度：赞同 / 反对；
- 人设口吻；
- 敌意或攻击性。

## 七、权利要求草稿（供代理人参考）

**1.**（独立方法权利要求）一种大语言模型中属性承载注意力头的定位方法，其特征在于，包括：

- 获取多个内容组。对每个内容组构造多个属性变体输入，每个属性变体输入依次包含：
  - 体现该变体属性的属性承载段；
  - 在同一内容组的各属性变体之间分词后逐 token 相同的锚点段。
- 将各属性变体输入送入大语言模型做前向计算，获取各注意力头在所述锚点段对应 token 位置上的输出，并聚合为每个输入、每个注意力头的锚点特征向量。
- 对每个注意力头，基于所述锚点特征向量计算承载分数。所述承载分数表征：在扣除内容组之间的差异后，属性变体之间的差异所解释的变化比例。
- 根据所述承载分数，从所述注意力头中选出属性承载注意力头。

**2.** 根据权利要求 1 的方法，其特征在于，所述承载分数为 SS_attr / (SS_tot − SS_scn)。其中：

- SS_tot 为锚点特征向量相对总均值的平方和；
- SS_scn 为内容组均值相对总均值的平方和；
- SS_attr 为各属性在组内残差上的均值的平方和。

**3.** 根据权利要求 1 的方法，其特征在于：

## 八、关键保护点（区别于现有技术）

1. **内容不变锚点**：属性段之后接一个在同一内容组内逐 token 相同的锚点段，**只在锚点位置**读取头输出。这样分离出的是属性的**搬运**，而不是字面读取。ITI 和 Wang 等人 2025 的方法都不具备这一点。
2. **组内属性方差占比**：作为承载分数，是闭式计算，**不训练逐头探针、不做逐头干预**，计算量与头数无关，并且在扣除内容方差后计算。
3. **持续注入**：在承载头上于提示末尾及每个生成步持续注入。实验中，只在锚点位置做一次性干预几乎无效（+0.04），持续注入则显著有效（+1.19）。
4. **跨模型迁移与层窗口**：同一组锚点样本可直接用于新模型；可读性峰值所在层窗口在多个模型中位于相对深度约 0.43–0.56。

## 九、可替代方案（建议写入说明书以扩大保护范围）

- **锚点**：可以是事实摘要、固定提示语、固定问题，或者任何在组内相同的 token 序列；可以只取锚点的一部分 token，或对锚点 token 加权平均。
- **承载分数**：可以替换为组内属性的 F 统计量、组内线性判别比（Fisher 比）、组内可读性 AUROC 或互信息等。凡是“扣除内容组差异之后衡量属性差异”的统计量，都在保护范围内。
- **部件**：除注意力头外，同一方法也适用于 MLP 神经元、稀疏自编码器特征、注意力输出整体或残差流方向。
- **属性取值**：可以是离散类别，也可以是连续值，连续值时用组内回归的 R² 代替方差占比。
- **调控方式**：可以是加法注入、投影消除、乘性缩放，或替换为供体激活。
- **模型结构**：仅解码器的 Transformer、编码器-解码器、多模态模型的语言部分、分组查询注意力（GQA）、多查询注意力（MQA）结构都适用。
