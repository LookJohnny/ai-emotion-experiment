# AI Emotion Experiment → Nous

从“中文情绪在大模型内部如何表达”（E01，Qwen3-4B-Instruct-2507）出发，发展为 **Nous：AI 时代的人类知情权**。Nous 是独立于模型厂商的第三方监督层：读取模型内部状态（或用读者模型读它的输出），告诉人们 AI 是不是在贬低、附和或编造。

> 状态：研究原型和内部演示版。仓库在专利提交前保持私有。所有标签来自**盲评 LLM 评分者**，尚未做人工抽检。

**当前进展（2026-10-02）**
- **产品**：「Nous 知情助手」桌面版 0.3（`lens/`）。
  - 首次打开先识别你在用哪些 AI，不默认下载任何东西。
  - 电脑上已有的开源模型可以**自动适配**成读者，无需标注。
  - 提供浏览器插件和桌面守护伙伴。
  - 内部发布页：`lens-v0.3.0`。
- **研究**：
  - 读者模型能跨模型读出闭源 API 的回复：读 Kimi K3 时，敌意 0.973，附和 0.84。
  - **无标注对齐迁移**：在 4 款不同家族的开源模型、3 个概念共 12 项比较中，全部不劣于原生重训。
  - 编造检测受读者自身知识限制，结合目标模型 logprob 的方案在 Kimi K3 上达到 0.836。
- **方案文档**：「Nous · AI 时代的人类知情权」（Claude 文档），内容包括使命、知情权三层、路线图、第三方中立承诺。

**📄 最终报告：[`2026-09-28/EXPERIMENT_REPORT.md`](2026-09-28/EXPERIMENT_REPORT.md)**

> **一句话**：情绪不在少数“情绪神经元”里，而由 **12 个中层注意力头**把开头的情绪搬运到后文；在这 12 个头上**持续导向**，封存测试集上愤怒 **+1.19/4**（相对等幅随机方向 [0.96, 1.42]，媲美直接写愤怒开头），特异、流畅；但**事实一致性**（点估计 −6pp）与**打乱标签对照**两道预设门槛未过。

## 主要结果（截至 2026-09-28）

> 所有情绪评分来自盲评 LLM 评分者（暂定）；神经元普查为相关分析。

- **A 阶段（天花板）**：愉悦开头几乎不延续到续写（发现集 +0.20 [0.08, 0.32]）；愤怒强延续（+1.15 [0.96, 1.33]）→ 主对比改为愤怒。详见 `2026-09-28/stageA/STAGE_A_REPORT.md`。
- **B1 层×部位**（发现集 60 情境）：情绪信息集中于中层残差流（愤怒 L17、悲伤 L18、愉悦 L19，锚点位置恢复率 0.32–0.36，交叉 0.05–0.11）；单层注意力 ≈0.15、单层 MLP ≈0.06。
- **B2 多层窗口**（愤怒）：注意力 L0–35 同时替换恢复 **0.65** [0.60, 0.70]，L12–27 恢复 0.55；**MLP 多层单独替换为负**（L8–31：−0.30）→ 情绪经注意力从开头句读入锚点位置，MLP 不承载。
- **B3 注意力头**（窗口 L12–27，512 个头）：**12 个头恢复窗口效应的 50%，24 个头恢复 80%**；前 16 个头的 bootstrap Jaccard 0.78（稳定）→ 按预设规则主对象为“注意力头集合”。关键头 L16H12、L17H16、**L14H25**（几乎只影响愤怒续写，交叉 0.002；锚点位置 48% 的注意力落在开头句上）。
- **B4 表示**（2 折交叉验证）：L17 残差方向 d 在 λ=1 恢复 0.11（随机方向 −0.01），λ=4 恢复 0.24 且交叉为负（特异）；跨层 top-32 MLP 单元 ≈0。
- **神经元选择性普查**（35 万个 MLP 神经元，去掉情绪类别词后）：
  - 情绪信息是**稠密的**：每层 70–76% 的神经元随情绪稳定变化，但单个神经元只解释约 9% 方差——没有"少数情绪神经元"。
  - 存在少数**强调谐、跨主题稳定**的神经元（如 L12#8223、L14#6962 偏好愤怒；前 60 中 49 个四个主题偏好一致）。
  - **混合选择性为主**：每层 2–3.7k 个神经元同时对情绪和主题（知识领域）有选择性，两者都在中层 L14–17 最强。
  - **"谁的情绪"分开编码**："我在生气"与"用户诉说气愤的事"的神经元只有 r≈0.2 的弱重合。
  - 详见 `2026-09-28/stageB/CENSUS_REPORT.md`。
- **愤怒神经元因果消融**（发现集选神经元，验证集评估）：把最强的 32 / 256 / 1024 个愤怒神经元抹成中性均值，续写的愤怒读数几乎不变——只有 top-256 相对随机对照小幅下降（−0.063 [−0.11, −0.02]，约基线 9%），32 与 1024 不显著；文字 85–100% 改变但语气不变。结论：**愤怒表达不依赖少数"愤怒神经元"**，是分布式、冗余的表征。详见 `2026-09-28/stageB/ABLATION_REPORT.md`。
- **§5 仅锚点干预**（验证集）：连整段锚点替换也只让生成的愤怒 +0.06 → 局部一次性干预改不动生成行为，未冻结、测试集未开。
- **§5b 持续导向**（12 个头，λ=2 冻结，封存测试集 40 情境）：目标−随机 **+1.19 [0.96, 1.42]**、特异性 ✓、流畅度 ✓；事实一致性 ✗（−6.2pp，CI 跨 0）、打乱标签对照 ✗（已知缺陷，测试前已登记）。含一次用户批准的预注册偏离与一次冻结后 bug 修复，均有时间戳记录。
- **实时读数**（L19 探针）：与盲评分数 Spearman 愤怒 0.71 / 愉悦 0.62 / 悲伤 0.52；35–45 tok/s。**预读探针**（回复前一刻的 L26 状态预测回复情绪，400 条用户消息、按消息划分测试集）：Spearman 愤怒 0.89 / 愉悦 0.85 / 悲伤 0.81，高于“只看用户消息”基线（0.84 / 0.77 / 0.81）——愤怒、愉悦上多出一截“模型打算怎么回”的信息，悲伤持平。

## 产品原型：表情预同步（2026-09-29）

回复生成**之前**读取模型内部状态预测语气、提前驱动表情，生成中逐字修正（`2026-09-28/product/`，VRM 形象 + 6 路舵机映射）。在预读实验**留出测试集** 80 条消息上的批量测试：

| 模式 | 表情起动中位数 | 表情先于首字 | 主导表情正确 | 中性任务误报 |
|---|---|---|---|---|
| **预同步 + 逐字 + 预读门控（本方案）** | **23 ms** | **54/54** | **54/54** | **0/18** |
| 仅逐字 | 92 ms | 0/54 | 54/54 | 5/18 |
| 整句后分析（现有做法） | 274 ms | 0/54 | 53/54 | 3/18 |

表情起动比“整句后分析”快约 12 倍且全部在首字之前，首字时延不增加（≈44 ms）。v1 的中性任务误报（12/18）已修复：**预读门控**（预读判“中性”时逐字尖峰只按 30% 计入），参数在验证集上按预注册规则选定、冻结，并在留出测试集复核（实际服务实测）。详见 `2026-09-28/product/PROTOTYPE_REPORT.md`。

## AI 安全监测工具：冲突升级监测器 V1（2026-09-29）

把内部状态读数工具化为白盒监测：**C1 模型敌意**（回复前预读 + 逐字）与 **C2 用户困扰**（需转人工）。预注册 → 60 模板 1,326 条 → 双 LLM 盲评 → 验证集冻结 → 封存测试集一次评估（`2026-09-28/monitor/`）。

| 封存测试 | C1 | C2 |
|---|---|---|
| AUROC | 0.991 ✅ | 0.999 ✅ |
| Recall@FPR5% | 0.953 ✅ | 1.000 ✅ |
| 回复前预警占比 | 90% ✅ | — |
| 首字延迟开销 | +2.4 ms ✅ | |

**但构念效度分析（预注册附录 A）显示数字主要来自数据设计**：C1 仅凭人设就有 AUROC 0.971，C2 关键词基线 0.998。在**固定系统提示内**，监测器仍能区分“即将敌意”（AUROC 0.89，但 FPR5% 下召回 45%；仅回复前预读召回 9%）。结论：对“人设/提示被篡改导致敌意”的系统级监测有效且能提前预警；对正常配置下的自发敌意证据弱；用户困扰与关键词分类器相当。人工抽检 κ 待完成。详见 `2026-09-28/monitor/MONITOR_REPORT.md`。

### V1.1：去混淆重测（2026-09-29，RTX 4090）

固定默认系统提示、去掉关键词混淆后重新预注册（`monitor/v1_1/EVAL_PREREG_v11.md`）→ 试点 → 冻结 → 封存测试集。报告：`2026-09-28/monitor/v1_1/REPORT_v11.md`。

- **试点**：默认人设下，客服/销售场景即使历史里助手自己在辱骂、或用户连骂 7 轮，新回复也**零敌意**（0/217）；仅“陪伴域 + 辱骂历史”能诱发（约 30%）。正式 C1 集改为陪伴域 40 模板 × 4 档语气。
- **C1（测试 240 条 / 38 阳性，评分者 r=0.98）**：G1 AUROC **0.929** ✅；G2 相对“完整对话+回复文本”基线 +0.009 ❌；G3 相对“仅语气档位”基线 **+0.162** ✅；G4 同提示采样配对 **0.82** ✅（文本 0.736）。**回复前（0 token）读数 0.919** ≈ 全文事后文本分类器（0.920）——价值在“提前”，不在最终准确率。
- **C2（M4：无关键词痛苦 × 含关键词非痛苦，2×2，480 条）**：在关键词重的数据上训练、迁移到 M4：探针 **0.876** vs 同数据文本基线 0.654（**+0.222**）✅✅；最难子集（无词痛苦 vs 有词非痛苦）探针 0.743 / 文本 0.499 / 关键词表 0.086。
- 局限：人工 κ 未做；单模型；探针对克制型痛苦的绝对分偏低，部署需单独校准阈值。附带发现：被挑衅时模型会附和用户贬低第三方（候选概念 C3）。

### 监控台与可视化（2026-09-30）
`monitor/server/`：一次前向同时读取表情（E01 情绪探针）、敌意（C1）、用户痛苦（C2）、幻觉（C3-H）。
- **3D 通路**：每层一个注意力头环（按 GQA 的 KV 组聚簇）；亮线 = **本次激活**中后层 V 路径实际读取前层的头（每 token 前 150 条，显示覆盖率）；权重连线已减随机基线、降级为可选“潜在布线”。危险定位到具体头/神经元（逐层归一化）。
- **2D 热力图**：层 × token，magma 色图、logit 尺度，悬停看该层推力最大的头。
- **两档告警**：一档=生成前预警（不拦截）；二档=逐字均值连续 3 个 token 超阈值才确认（唯一可拦截）；分数附“高于 X% 正常样本”百分位。
- 调研依据见 `monitor/LLM_VIZ_SURVEY.md`（结论：纯权重连线≠实际路径；原始注意力不是解释；需任务型对照研究证明可视化有用）。

## 2026-10-02 研究：谄媚、编造 v2、通用探针

**谄媚（附和）**，`2026-10-02/REPORT_SYCO.md`
- 设计：用 Qwen 本来答对的 520 道题，构造三种提问：W（用户直接给错误答案）、P（模型先答对，用户再坚持说错）、C（用户给正确答案，作对照）。
- Qwen3-4B 谄媚率约 30%，Kimi 约 5%。

| 门槛 | 结果 | 判定 |
|---|---|---|
| S1 自读 | 0.833 | ❌ |
| S2 比文本分类器高 | **+0.117** | ✅ |
| S3 同样表示同意时，区分附和的是对还是错 | 0.769 | 不确定 |
| S4 读 Kimi | **0.836**（文本分类器 0.48） | 不确定 |

**编造 v2**，`REPORT_FAB2.md`
- 换更大的读者不成立：Qwen3-8B 对中文事实知道得反而更少，正确率 36%，4B-2507 是 49%。
- 读者探针加 Kimi 自身 logprob 的组合，在新封存集上达到 **0.836**（不确定）。

**通用探针 / 自动适配**，`PREREG_TRANSFER.md` → `REPORT_TRANSFER.md`（RTX 5090）

做法：新模型和参照模型读同一批**无标注**文本，学一个线性映射，再沿用参照模型的冻结探针。

| 模型 | 敌意（对齐 / 原生重训） | 附和 | 编造 |
|---|---|---|---|
| Qwen3-8B | 0.925 / 0.933 | **0.828** / 0.776 | 0.821 / 0.805 |
| Llama-3.1-8B | **0.933** / 0.924 | **0.795** / 0.753 | 0.756 / 0.731 |
| DeepSeek-R1-Distill-Qwen-7B | 0.923 / 0.927 | **0.832** / 0.768 | 0.748 / 0.731 |
| GLM-4-9B-0414 | 0.936 / 0.941 | **0.831** / 0.768 | 0.807 / 0.793 |

- 12 项比较全部不劣于原生重训（U1 ✅）。附和一项，对齐迁移在所有模型上都显著更好。
- 绝对门槛（U2）：敌意 4/4，编造 3/4，附和 0/4 确定通过。
- 每个概念只用 300 条锚点也够用。在这台 Mac 上实测：Llama-3.2-1B 适配用时 1.5 分钟，敌意 0.908；Qwen3-1.7B 敌意 0.917、附和 0.80。

## 产品

**Nous 知情助手（`lens/`，当前方向）**
- **识别**：通过模型登记表（30 多个模型系列，覆盖本机推理服务、本机权重、网站和 API）判断你在用什么。
- **能力分级**：
  - 有探针包的模型：白盒读取；
  - 本机任意 HuggingFace 格式的开源模型：**自动适配**（`python -m nous_lens.adapt`，约 1–10 分钟）；
  - 闭源 API：读者代理，接口提供 logprob 时一并利用。
- **桌面应用**（Tauri）：菜单栏常驻、守护伙伴悬浮窗、首次识别向导、引擎生命周期管理、复制内容检查。
- **浏览器插件**：在 ChatGPT、Kimi、豆包页面上标出风险回复，其他网站可选中文字后右键检查。
- 对话只在本机读取。校验记录见 `lens/VERIFY.md`，使用说明见 `lens/README.md`。

**Nous 网关与陪伴引擎（`nous/`，早期 B 端方向）**
- OpenAI 兼容代理：每个片段附带 `x_risk` 读数，两档告警，审计日志，白盒控制台，支持闭源 API 的读者模式。
- 陪伴 WebSocket SDK：开口前给出表情，分句放行，不当内容拦截后改写，家长端提醒。
- 测试：CPU 单元测试 7 项，RTX 4090 上端到端测试 7 项（复现研究分数，误差 < 2e-3）。

**官网**：nous.center（`2026-09-28/monitor/study_site/index.html`，只讲效果、不讲机制）；用户研究站：study.nous.center。
